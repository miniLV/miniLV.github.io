用 Jev 做 Codex 逐调用模型路由

编码任务里，难题与例行步骤常常交替出现。Jev Auto Router 的目标是在同一个 Codex 会话中， 为每次有意义的模型调用选择合适的 GPT 模型与推理档位，并在任务结束后独立验收。

这里的 Jev 来自 TypeSafe：对宿主当前确实可请求的 (模型, reasoning effort) 组合做一次 typed Choice。本地 Responses 代理负责保持会话与工具循环连续； 任务边界再做独立验收。Router Compass 把选路、实际用量和验收结果放在一起。

先说清楚状态。

架构已定，运行时仍是原型验证阶段。真实 Codex 工具循环中的跨模型切换、完整验收链和节省效果尚未端到端验证。 本文说明设计与前置条件，不是「安装后即可自动路由」的承诺，也不宣称普遍省钱。

前置条件

  • TypeSafe 账号与 Jev API key（代理读取 JEV_API_KEY；也可与 TYPESAFE_API_KEY 设为同一密钥）。
  • Node.js 22+、已登录的 Codex CLI。
  • 宿主实际可请求的模型与推理档位。

只有 Jev 密钥，不足以运行真实的逐调用路由。

一次调用怎么走

  1. 本地代理接住调用：检查路由是否关闭、是否为基础设施调用，并只列出宿主可请求的组合。
  2. Jev 做唯一语义选择：一次 Choice 同时决定模型与档位。普通候选是 Luna Max、Terra、Sol；GPT-6 默认不可选。
  3. 执行门禁只校验：结果只有 ALLOW 或 DENY，不会偷偷改选。超时、低置信或无效回答回退到 Terra/medium，并留下原因。
  4. 原生 Responses 执行：保持 Codex 会话与工具循环；日志记录实际模型、档位、用量和回退原因。

路由正确 ≠ 任务完成

任务结束后的独立验收会对照原始需求检查改动、测试、运行结果和必要的语义结论；执行模型自报成功不算证据。 验收失败时，把具体失败事实送回同一会话纠错；默认最多两轮，之后由 Root 接管。验收本身使用固定档位，不参与节省型路由。

本地验证命令

以下命令验证当前原型代码，不会建立 Codex 的生产代理连接：

npm ci
npm test
npm run typecheck
